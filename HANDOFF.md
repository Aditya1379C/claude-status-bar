## Plan usage: attempted, dropped (do NOT re-attempt without a new data source)
Goal was a menu-bar warning off the plan quota (5h/7d `used_percentage`). Built it, then dropped it because there is no source that refreshes during **desktop-app** use, which is how the user mostly works. Findings (all verified this session, so future sessions can skip the legwork):
- The ONLY channel exposing `rate_limits` (`five_hour`/`seven_day` `{used_percentage, resets_at}`) is the Claude Code **statusLine** stdin JSON. Confirmed live. It is a CLI/TUI feature: the desktop app fires hooks but never a statusLine, so the data froze the moment the last CLI session ended (verified: `usage.json` ts stayed fixed across an hour of active desktop work).
- No headless `claude usage` command exists (checked `claude --help`; `claude usage` just treats "usage" as a prompt).
- Keychain OAuth token + undocumented usage endpoint is NOT viable: the app is **ad-hoc signed** (`flags=…adhoc`, no TeamIdentifier), so a keychain "Always Allow" grant would die on every rebuild (only a Developer-ID build gets a durable identity); and it repurposes a cross-service credential (the safety layer blocks the read, correctly). The item exists (`svce="Claude Code-credentials"`, `acct="adityajaisingh"`); value is ACL-gated.
- Desktop app persists NO usage data on disk: searched `~/Library/Application Support/Claude` (Local Storage, Session Storage, IndexedDB, config/Preferences, audit.jsonl). Only transient, compressed Chromium IndexedDB blobs, not pollable.
- UX trap noticed: a live reset countdown (`resetsAt - now`) makes a frozen reading look like it is updating. If ever revisited, do not show a live countdown on stale data.
- Reopening this needs a genuinely new source (e.g. Anthropic exposes plan usage to statuslines/hooks — open req GitHub #11535 — or a Developer-ID build + user-blessed keychain read against a then-documented endpoint).

## Gotchas
- **Merging upstream: git silently drops our additions adjacent to upstream-deleted lines** (no conflict marker). After any upstream merge, diff function lists vs the pre-merge commit (`comm -23 <(git show <pre>:Sources/main.swift | grep -oE 'func [a-zA-Z]+\(' | sort -u) <(grep -oE 'func [a-zA-Z]+\(' Sources/main.swift | sort -u)`) and BUILD — the compiler catches lost selectors. 0.3.4 merge lost `chooseHideIdle`/`soundEdgeDone`/completion.mp3 this way.
- Upstream removed the completion-sound feature in 0.3.3; the fork keeps it. `build.sh` must `cp assets/completion.mp3` into Resources (re-add if a future merge drops it) or the toggle is silently dead.
- Filtered-build check: `head` always exits 0; capture output in a var and test `-z`.
- Version 0.3.2 does NOT re-copy statusbar JS on relaunch; `install.js` runs on version change.
- `install.js` reorders the `hooks` block in settings.json when re-run (cosmetic; PermissionRequest lands last). It also writes a `settings.json.bak-statusbar` on first run.
- Thaw (menu bar manager) can swallow a newly-added status item; reset Thaw's layout if the icon vanishes.
